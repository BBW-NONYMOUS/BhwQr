# @bhw/web — BHW QR Attendance System (web)

Admin portal, registration, employee self-service (`/me`) and the full-screen kiosk for the
Barangay Kalawag II Health Workers Office.

Stack: Next.js 16 (App Router, Turbopack, `proxy.ts`), React 19, TypeScript (strict), Tailwind CSS v4,
shadcn/ui, Supabase (`@supabase/ssr`).

## Run it

From the repository root:

```bash
pnpm install                       # once, installs the whole workspace
pnpm db:start                      # local Supabase (Docker) - prints URL + keys
cp apps/web/.env.example apps/web/.env.local   # then paste the keys from `supabase status`
pnpm dev:web                       # http://localhost:3000
```

Scripts (run with `pnpm --filter @bhw/web <script>` or inside `apps/web`):

| Script      | What it does                                             |
| ----------- | -------------------------------------------------------- |
| `dev`       | Next.js dev server (Turbopack) on port 3000              |
| `build`     | Production build                                         |
| `start`     | Serve the production build                               |
| `lint`      | ESLint (`eslint-config-next` + Prettier compatibility)   |
| `typecheck` | `tsc --noEmit`                                           |
| `test`      | Vitest unit tests (jsdom) - `lib/**/*.test.ts`, `components/**/*.test.tsx` |
| `test:e2e`  | Playwright tests in `e2e/` (starts `pnpm dev` itself). Run `pnpm exec playwright install chromium` once. |

## Environment variables

Copy `.env.example` to `.env.local`. Validation lives in `lib/env.ts` (public) and `lib/env.server.ts`
(server-only); a missing or malformed value throws a readable error on first use.

| Variable                        | Scope           | Notes                                                                 |
| ------------------------------- | --------------- | --------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`      | public          | Local default `http://127.0.0.1:54321`                                |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | public          | Anon / publishable key. RLS protects the data.                        |
| `NEXT_PUBLIC_APP_URL`           | public          | Origin used for auth email redirects (`/auth/callback`). Default `http://localhost:3000` |
| `SUPABASE_SERVICE_ROLE_KEY`     | **server-only** | Bypasses RLS. **Never** prefix with `NEXT_PUBLIC_`; only `lib/supabase/admin.ts` reads it. |

Shared code comes from the workspace: `@bhw/types` (enums, zod schemas, error codes) and
`@bhw/design-tokens` (colors, radius, typography). Both ship TypeScript source and are compiled
by Next through `transpilePackages`.

## Theming

`app/globals.css` imports Tailwind, then `@bhw/design-tokens/web.css`, which is generated from
`packages/design-tokens/src/tokens.ts` and defines the shadcn CSS variables (`--background`,
`--primary`, ...), the health-teal `brand` color, status colors and chart colors for light and
`.dark`. Do not redefine those variables in `globals.css`; change the tokens and run
`pnpm --filter @bhw/design-tokens build`. `globals.css` only adds what the tokens do not cover
(sidebar variables mapped onto token colors, base layer, reduced-motion rule).

Useful token utilities: `bg-brand text-brand-foreground`, `bg-background-subtle`,
`bg-status-on-time text-status-on-time-foreground` (also `late`, `absent`, `incomplete`,
`undertime`) - prefer `<StatusBadge status="late" />`.

Font: Inter via `next/font/google` (`--font-inter`, used by `font-sans`). Radius: 6px controls
(`rounded-md`), 12px cards (`rounded-xl`), full-round badges.

## UI library rules

shadcn/ui is always the first choice. Other libraries are allowed **only** for the role below and
never two libraries for the same component type. All of them must use the same Tailwind tokens.

| Library                         | Used for (only)                                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **shadcn/ui** (primary)         | Every core component and the starting layouts (login/signup, sidebar shell, dashboard, charts)       |
| **Magic UI**                    | Animated number counters on dashboard stat cards; subtle animated border on the kiosk QR card        |
| **Aceternity UI**               | Background effect on the login / register left panel only - never on data pages                      |
| **Motion** (`motion/react`)     | Page and dialog transitions, live-scan list enter animation, kiosk QR refresh fade                   |
| **Lucide React**                | All icons                                                                                             |
| **Recharts** (via shadcn Chart) | All charts - always through `components/ui/chart.tsx`                                                 |
| **next-themes**                 | Light / dark / system mode                                                                            |

Magic UI and Aceternity components are added in Phase 4 through the shadcn CLI
(`pnpm dlx shadcn@latest add "https://magicui.design/r/<name>.json"` and the Aceternity registry),
so they land in `components/` as editable source using the same tokens.

Supporting libraries: TanStack Table (shadcn data-table pattern), react-hook-form + zod
(`components/ui/form.tsx`, schemas from `@bhw/types`), `qrcode.react` (kiosk QR),
`@yudiel/react-qr-scanner` (admin fallback scan page), `@react-pdf/renderer` (DTR and report PDFs),
`date-fns` + `@date-fns/tz` (all dates in `Asia/Manila`), `sonner` (toasts).

Animations must respect `prefers-reduced-motion` (a global rule in `globals.css` disables CSS
animations; use Motion's `useReducedMotion` for JS animations) and must never slow down tables,
data pages or the kiosk.

## Auth and routing

`proxy.ts` calls `updateSession()` from `lib/supabase/middleware.ts` on every non-static request
so Supabase auth cookies stay fresh. Route rules live in `lib/auth/routes.ts`:

| Route(s)                                              | Access                 |
| ----------------------------------------------------- | ---------------------- |
| `/`, `/login`, `/register`, `/privacy`, `/auth/callback` | public              |
| `/pending`, `/rejected`                               | signed-in, any status  |
| `/admin/**`                                           | admin                  |
| `/viewer/**`                                          | viewer, admin          |
| `/me/**`                                              | employee               |
| `/kiosk/**`                                           | kiosk, admin           |

Row Level Security in Postgres is the real security boundary; the route map only decides where to
send users.

## Next.js 16 notes

- `middleware.ts` is now `proxy.ts` (Node.js runtime by default).
- `cacheComponents` is enabled (create-next-app default). Request-time APIs (`cookies()`,
  `headers()`, the Supabase server client) must be read inside a `<Suspense>` boundary or a
  dynamic segment; static shells are prerendered.
- Tailwind v4 is compiled by the `@tailwindcss/turbopack` loader configured in `next.config.ts`
  (no PostCSS config).
