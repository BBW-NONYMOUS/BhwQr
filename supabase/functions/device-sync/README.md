# `device-sync` – contract for a future fingerprint terminal

> **Role speaking: Backend Developer** (FR-116, FR-117)

Lets a biometric terminal at the BHW office submit attendance punches into the **existing**
tables without schema changes. The terminal does the fingerprint match locally; **no biometric
data is ever sent** — only the matched employee's BHW ID number.

## Setup

1. Admin creates a `stations` row for the terminal (name, coordinates, active).
2. System Administrator sets the secret: `supabase secrets set DEVICE_SYNC_API_KEY=<random 32 bytes>`.
3. The terminal is configured with the endpoint, the station ID and the API key.

## Request

`POST https://<project>.supabase.co/functions/v1/device-sync`

Headers: `Content-Type: application/json`, `x-api-key: <DEVICE_SYNC_API_KEY>`

```json
{
  "stationId": "b7e41a09-6c2d-4e83-a5f0-1d9c8b3e7a42",
  "terminalSerial": "ZK-K40-000123",
  "events": [
    {
      "eventId": "4d7c2a1e-9b3f-4e8a-8c61-2f0d9e7b5a13",
      "bhwIdNumber": "BHW-KII-2019-001",
      "occurredAt": "2026-11-09T07:58:12+08:00",
      "direction": "auto"
    }
  ]
}
```

| Field | Rule |
| --- | --- |
| `eventId` | UUID generated by the terminal, unique per punch. Re-sending the same event is safe (idempotent). |
| `bhwIdNumber` | Employee's BHW ID number as enrolled on the terminal. |
| `occurredAt` | ISO 8601 with offset. Within ±5 min of server time the **server time** is used (BR-02); older events are accepted as backfill with their own time and noted `(backfill)`. Future times are rejected. |
| `direction` | Informational only. The server decides time-in vs time-out with the same rules as QR scans (D-13, D-14). |
| `events` | 1–500 per request, processed oldest first. |

## Response `200`

```json
{
  "ok": true,
  "results": [
    { "eventId": "4d7c2a1e-…", "status": "recorded", "action": "time_in" },
    { "eventId": "91aa…", "status": "duplicate", "code": null },
    { "eventId": "77b0…", "status": "rejected", "code": "ACCOUNT_NOT_ACTIVE" }
  ]
}
```

| `status` | Meaning | Terminal should |
| --- | --- | --- |
| `recorded` | Punch stored | Mark event as synced |
| `duplicate` | Already received earlier | Mark event as synced |
| `rejected` | Business rule failed (`STATION_INACTIVE`, `ACCOUNT_NOT_ACTIVE`, `ALREADY_COMPLETED`, `FUTURE_TIME_NOT_ALLOWED`, `INTERNAL_ERROR`) | Mark as synced except `INTERNAL_ERROR` (retry later) |

Request-level errors use the shared format `{ ok:false, code, message }`: `AUTH_REQUIRED` (401, wrong/missing key), `RATE_LIMITED` (429, > 60 requests/min), `INVALID_REQUEST` (400).

## Storage mapping (no schema change)

| Terminal concept | Stored as |
| --- | --- |
| Terminal | `stations` row |
| Punch | `scan_attempts` row (`nonce` = `eventId`) + `attendance_records` time-in/out (`method = 'qr'`, `notes = 'device-sync: <station>'`) |
| Idempotency | lookup of `scan_attempts (employee_id, nonce)` |
| Errors | `error_logs` (source `edge_function`) |
